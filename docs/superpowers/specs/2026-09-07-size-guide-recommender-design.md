## 4. เอนจิน — `src/lib/fit.ts`

### 4.1 ข้อมูลเสื้อ

ดึง `SIZES` จาก `src/lib/sizes.ts` แล้วแปลงนิ้ว → ซม. ที่ระดับ module
เพื่อให้ `sizes.ts` ยังเป็นแหล่งอ้างอิงเดียวตามที่ README กำหนด

> **กับดัก:** `chest` ใน `sizes.ts` เป็น**เส้นรอบวง**อยู่แล้ว ต่างจาก `bodyWidth` (วัดแบน)
> ของ UNIQLO ที่ต้องคูณ 2 — ที่นี่ **ห้ามคูณ 2**

| ไซซ์ | รอบอก (ซม.) | ไหล่ (ซม.) | ความยาว (ซม.) | ช่วงน้ำหนัก (กก.) |
|---|---|---|---|---|
| XL | 124.46 | 63.50 | 83.82 | 80–91 |
| 2XL | 129.54 | 66.04 | 86.36 | 92–104 |
| 3XL | 134.62 | 68.58 | 88.90 | 105–117 |
| 4XL | 139.70 | 71.12 | 91.44 | 118–129 |
| 5XL | 144.78 | 73.66 | 93.98 | 130+ |

### 4.2 `MODEL` — ลอกจาก `data-size/sizeRecommender.ts` ห้ามแก้

```
X = sqrt(weightKg / (heightCm / 100))

chestCirc     = 19.644 * X - 27.734 + genderOffset.chest
shoulderWidth = 2.3811 * X + 25.956 + genderOffset.shoulder

genderOffset  female = { chest: 0, shoulder: 0 }
              male   = { chest: +5, shoulder: +3 }

ageCoef              = 0
fitPreferenceShiftCm = { tight: -6, slightlyTight: -3, standard: 0, slightlyLoose: +3, loose: +6 }
verdictBands         = { fit: 3, slight: 8 }
```

### 4.3 `OVERBEAR_TEE.intendedEase` — ค่าของเสื้อ ไม่ใช่ของโมเดล

`data-size/` เก็บ `intendedEase` ไว้ใน `StyleSpec` ไม่ใช่ `MODEL` และ back-solve ใหม่ทุกครั้ง
ที่เปลี่ยนเสื้อ (ของ UNIQLO ได้จาก back-solve เคส XS) ค่าของ OVERBEAR จึง back-solve
จากตารางน้ำหนักของแบรนด์เอง:

| มิติ | ค่า (ซม.) | ที่มา |
|---|---|---|
| `chest` | **+1** | sweep หาค่าที่ตรงกับตารางน้ำหนักมากที่สุด |
| `shoulder` | **+20.6** | ค่าเฉลี่ย ease ที่จุดกึ่งกลางช่วงน้ำหนักทั้ง 5 ไซซ์ (h=172) |
| `length` | **+12.4** | ยึดจาก XL ที่ 172 ซม. / 85.5 กก. |

> **ต้องเป็นคอมเมนต์ในโค้ด:** `chest: +1` **ไม่ใช่ ease จริงของ OVERBEAR**
> ถ้า fit เส้นโค้งร่างกายเข้ากับตารางของแบรนด์เอง จะได้รอบอกจริง 109.3 ซม. ที่ 172/85.5
> เทียบกับเสื้อ XL 124.46 ซม. → ease จริง = **+15.2 ซม.** ซึ่งเท่ากับ `intendedEase` +15
> ของเสื้อ oversized UNIQLO พอดี
> เลข `+1` คือ**ตัวหักล้าง**การประเมินเกินของเส้นโค้ง ไม่ใช่คำอธิบายทรงเสื้อ
> ใครลบเส้นโค้ง UNIQLO ออกเมื่อไหร่ ต้องเปลี่ยนค่านี้กลับเป็น +15 ทันที

### 4.4 มิติที่ 3 — ความยาวตัว (สูตรใหม่ ยังไม่คาลิเบรต)

`data-size/` ไม่มีสูตรประมาณความยาวลำตัว จึงต้องสร้างใหม่ ติดป้ายให้ชัดว่าเป็นของที่คิดขึ้นเอง
และไม่มีข้อมูลสังเกตรองรับเลยสักจุด ต่างจากสูตรอกกับไหล่ที่อย่างน้อยมีของ UNIQLO 2 จุด

```
requiredLength = 0.415 * heightCm + 0.6 * (X - 7.0)
```

พจน์แรกคือความยาวที่ต้องคลุมตามส่วนสูง พจน์ที่สองคือค่าเผื่อพุงเล็ก ๆ
(พุงใหญ่ดึงชายเสื้อด้านหน้าให้สูงขึ้น จึงต้องการความยาวเพิ่ม) — ที่ 137 กก. เพิ่มแค่ 1.16 ซม.

### 4.5 การเลือกไซซ์และคำตัดสิน

```
targetChestCirc = bodyChest + intendedEase.chest + fitPreferenceShift
recommendedSize = argmin | garmentChestCm - targetChestCirc |     // กรณีเสมอกัน -> ไซซ์เล็กกว่าชนะ

ต่อมิติ:  ease  = garment - body
          delta = ease - (intendedEase + fitPreferenceShift)
          |delta| <= 3   -> พอดี
          3 < delta <= 8 -> หลวมเล็กน้อย    |  -8 <= delta < -3 -> คับเล็กน้อย
          delta > 8      -> หลวม            |  delta < -8       -> คับ
```

`argmin` วิ่งบน 5 ไซซ์เท่านั้น จึงถูก clamp อยู่ใน XL–5XL โดยธรรมชาติ — **ตัดฟิลด์ `outOfRange`
ทิ้งทั้งหมด** ไม่มีข้อความ "คุณเล็ก/ใหญ่เกินกว่าไซซ์ที่เรามี" ตามผลตัดสินข้อ 5

`recommend()` คืน `perSize` ครบทั้ง 5 ไซซ์ (ไม่ใช่ไซซ์เดียว) เพื่อให้แท็บเปิดดูได้ทุกไซซ์

## 5. UI

### 5.1 หน้าฟอร์ม

| ช่อง | รายละเอียด |
|---|---|
| เพศ | `<select>` — placeholder "โปรดเลือกเพศของคุณ" · ค่า หญิง / ชาย |
| อายุ | `<input type="number">` — "โปรดกรอกอายุของคุณ" |
| ส่วนสูง (ซม.) | `<input type="number">` 50–260 · placeholder "50 - 260" |
| น้ำหนัก (กก.) | `<input type="number">` 10–200 · placeholder "10 - 200" |
| ความพึงพอใจในขนาดเสื้อผ้าที่สวมใส่ | radio 5 ระดับ · ป้าย รัดรูป — มาตรฐาน — หลวม · default = มาตรฐาน |

ปุ่ม "ดำเนินการต่อ" disabled จนกรอกครบและอยู่ในช่วง · ปุ่มรอง "ย้อนกลับ" ปิด dialog
คำโปรยหัวฟอร์มตามต้นฉบับ: *"เราจะแนะนำไซซ์ตามเพศ อายุ ส่วนสูง น้ำหนัก และความพึงพอใจ
ในการสวมใส่เสื้อผ้าของคุณ"*

> **อายุถูกเก็บแต่ไม่ถูกใช้** (`ageCoef = 0`) — เป็นผลจากการตัดสินใจข้อ 2 ที่เลือกให้เหมือน
> UNIQLO ทุกช่อง รีวิวข้อ 8 ชี้ว่านี่เป็นประเด็น PDPA ถ้าจะตัดทีหลัง แก้ที่ฟอร์มอย่างเดียวพอ
> เพราะเอนจินไม่ได้พึ่งค่านี้

### 5.2 หน้าผลลัพธ์

เรียงจากบนลงล่าง:

1. แถบสรุปโปรไฟล์ + ปุ่ม "เปลี่ยน" → กลับหน้าฟอร์ม **โดยค่าที่กรอกยังอยู่ครบ**
2. หัวเรื่องตามคำตัดสินของไซซ์ที่กำลังดู — **ยึดคำตัดสินของ "รอบอก"** เพราะเป็นมิติเดียว
   ที่ขับการเลือกไซซ์ (ไหล่กับความยาวรายงานเป็นผลพลอยได้ ตามพฤติกรรมที่สังเกตได้จาก UNIQLO)
   แมปเป็น: พอดี → "นี่คือไซซ์มาตรฐาน" · หลวมเล็กน้อย → "ไซซ์นี้หลวมเล็กน้อย" · หลวม →
   "ไซซ์นี้หลวม" · คับเล็กน้อย → "ไซซ์นี้รัดรูปเล็กน้อย" · คับ → "ไซซ์นี้รัดรูปมาก"
3. แท็บ 5 ไซซ์ (XL–5XL) ไซซ์ที่แนะนำมีป้าย "ที่แนะนำ" กำกับ
4. หุ่น SVG + เส้นทับ 3 เส้น พร้อมเส้นโยงไปป้ายคำตัดสิน
5. ลิสต์ 3 แถว: ชื่อมิติ · คำตัดสิน · **ตัวเลข `delta`** ("กว้างกว่าทรงที่ตั้งใจ +3 ซม.")
6. ตารางขนาดเต็ม XL–5XL จาก `SIZES`
7. ปุ่ม "ปิด"

**ทำไมโชว์ `delta` ไม่ใช่ `ease`:** คำตัดสินคำนวณจาก `delta` ถ้าเอา `ease` มาวางคู่กัน
ตัวเลขกับคำพูดจะสวนทาง — เช่น ไหล่ที่ `ease = +17.5` แต่ `intendedEase = 20.6`
จะขึ้นว่า "คับเล็กน้อย" ทั้งที่เลขเป็นบวก ผู้ใช้อ่านแล้วสรุปว่าเครื่องมือพัง

### 5.3 หุ่น SVG

inline SVG ตัวเดียว ทรงพลัสไซซ์ มองจากด้านหน้า มีเส้นทับ 3 เส้น: ตะเข็บไหล่ · รอบอก · ชายเสื้อ

พาเลตต์เว็บไม่มีสีฟ้าแบบ UNIQLO จึงแมปเป็น: **พอดี** = `--text` · **หลวม / หลวมเล็กน้อย** =
`--tan` · **คับ / คับเล็กน้อย** = `--red-ink`

สีไม่เป็นตัวสื่อความหมายเพียงอย่างเดียว — มีคำตัดสินภาษาไทยกำกับทุกเส้น (WCAG 1.4.1)

### 5.4 a11y

WCAG AA เป็นมาตรฐานของ repo นี้อยู่แล้ว สิ่งที่ต้องมี:

- แท็บไซซ์ตาม WAI tabs pattern — `role="tablist"` + roving tabindex + arrow keys
- ทุก input มี `<label>` ผูกจริง ไม่ใช่ placeholder แทน label
- ขอบช่องกรอกใช้ `--line-input` (3.28:1) ตามกฎ 1.4.11 ของเว็บ
- resting state ทั้งหมดต้องอยู่ในบล็อก `prefers-reduced-motion` ที่มีอยู่แล้ว
- ปิดด้วย Esc / backdrop ได้ และ **ค่าที่กรอกไม่ถูกล้าง**

รีวิวจับบั๊กของ UNIQLO ไว้ 9 ข้อ — ดีไซน์นี้แก้ไปในตัว 3 ข้อเพราะยังไงก็ต้องเขียนใหม่:
ข้อ 1 (ตารางแสดงไม่ครบทุกไซซ์) · ข้อ 5 (แท็บไม่รับ arrow keys) · ข้อ 6 (คลิกนอกพาเนลแล้วค่าหาย)

### 5.5 Responsive

dialog เต็มจอที่ต่ำกว่า 560px ให้ตรงกับรูปอ้างอิงที่เป็นความกว้างมือถือ
ตารางขนาดในผลลัพธ์ใช้กฎเดียวกับ `.sizetable-wrap` — เลื่อนในกล่องตัวเอง ห้ามดันหน้าเลื่อนแนวนอน

## 6. การตรวจสอบ

repo นี้ไม่มี test runner และการเพิ่มเข้ามาถือว่าเกินขอบเขต จึงใช้ script เดี่ยว
`scripts/verify-fit.ts` รันด้วย `node --experimental-strip-types` ตรวจ 4 ข้อ:

1. **พอร์ตแล้วไม่เพี้ยน** — เคสจริง 2 เคสของ UNIQLO (`170/55 → XS`, `175/95 → XXL`
   พร้อมคำตัดสินรายมิติ) ยัง reproduce ได้เมื่อรันกับ `UNIQLO_465185`
2. **ความตรงกับตารางน้ำหนักไม่เลื่อน** — grid มาตรฐานคือ ส่วนสูง {165, 170, 172, 175, 180, 185}
   × น้ำหนัก {ขอบล่าง, กึ่งกลาง, ขอบบน} ของทั้ง 5 ไซซ์ = 90 เคส ต้องได้ **56/90 (62.2%)** เป๊ะ
   ช่วงของ 5XL ในตารางเขียนว่า "130+" ซึ่งไม่มีขอบบน — grid นี้กำหนดให้ขอบบน = **145 กก.**
   เพื่อให้ตัวเลขคำนวณซ้ำได้ ถ้าเปลี่ยนค่านี้ 56/90 จะเปลี่ยนตาม
3. **ความทนทาน** — กวาดทุก input ในช่วงที่รับ (50–260 × 10–200 ทั้งสองเพศ)
   ต้องคืนไซซ์ใน XL–5XL เสมอ ไม่ throw และไม่มี `NaN` ในผลลัพธ์
4. **slider ต้องเลื่อนไซซ์ได้จริง** — ที่ 172/110 ไล่ 5 ระดับต้องได้ 2XL → 4XL ไม่ใช่ค่าเดียวค้าง

จากนั้น `npx eslint src` และ `npm run build`

## 7. ข้อจำกัดที่รู้อยู่แล้ว (เขียนไว้ให้คนอ่านโค้ดรุ่นถัดไป)

1. **ตรงกับตารางที่พิมพ์อยู่เหนือปุ่มแค่ 62.2%** — เป็นผลโดยตรงจากการตัดสินใจข้อ 1
   ปรับได้ด้วยค่าคงที่ตัวเดียว (`intendedEase.chest`)
2. **คำตัดสินขัดกับไซซ์ที่แนะนำเองที่ปลายช่วง** — `172/85 → XL` แต่รอบอก "หลวม" ·
   `172/137 → 5XL` แต่รอบอก "คับ" ตกลงกันแล้วว่าแสดงตามจริง (ข้อ 6)
3. **ไหล่ขึ้น "พอดี" เกือบทุกคน** — ตาราง OVERBEAR ไล่ไหล่ +2.54 ซม./ไซซ์ ขณะที่ไหล่ร่างกาย
   ที่ประมาณได้โตแค่ ~1.1 ซม./ไซซ์ ทำให้ ease ทั้งช่วง XL–5XL ต่างกันแค่ 5.6 ซม.
   ซึ่งอยู่ในแบนด์ ±3 — มิติที่ให้ข้อมูลจริงคือความยาว
4. **สูตรความยาวไม่มีข้อมูลสังเกตรองรับเลย** ต่างจากอก/ไหล่ที่มีของ UNIQLO 2 จุด
5. **โมเดลเพศหญิงเข้าถึงได้แต่ไม่เคยตรวจกับเว็บนี้** และ `data-size/README.md` ระบุเองว่า
   offset เพศชาย (+5 / +3) ก็ยังไม่ verify
6. **ค่าวัดเสื้อมี tolerance การผลิต 1–2 ซม.** ซึ่งกินแบนด์ "พอดี" (±3) ไปเกือบครึ่ง

### ทางออกถ้าจะทำให้แม่นขึ้น

`data-size/README.md` หัวข้อ "ขั้นตอนคาลิเบรตต่อ" เขียนวิธีไว้แล้ว — เก็บผลจริงเพิ่มต่อเพศ
แล้ว solve `a`, `b` ใหม่ ถ้าเก็บของ OVERBEAR เองได้ (เช่นถามลูกค้าว่าซื้อไซซ์ไหนจริง)
จะแทนที่เส้นโค้ง UNIQLO ได้ทั้งชุด และข้อจำกัด 1–2 หายไปเอง
